## 概念

#### 通用多态
- 通用多态是中程序设计语言中提供的基本多态机制, 包括包含多态和参数多态
- 包含多态, 又称子类型多态或继承多态

- 破坏了封装性
## 异常处理

#### 内存泄漏
- 内存泄漏(Memory Leak)指程序在运行过程中 **未能释放不再使用的内存**

可能导致的原因:
- malloc 没有 free, new 没有 delete, new\[] 用了 delete 没有 \[]
 - 存在循环引用, 无法回收资源
 - 未关闭的文件, 句柄, 数据库连接
 - 父类析构函数*不是虚函数*: 父类引用子类对象 调用析构函数时, 不会调用子类的析构函数
     - 内存泄漏的例子: A* p = new A_derived(); delete p;
     - 所以一个类如果要被继承, 析构一定要是虚函数!
#### 类型安全
- **类型安全**指编程语言在编译或运行时能防止因*类型错误*导致的操作（如将字符串当整数使用），从而避免崩溃、数据损坏或安全漏洞
- 强类型安全: Java, C#, Rust, Swift, Haskell
- 弱类型安全: Python, ts
- 不安全: C/C++, js

C++ 可能有野指针, 不自动检查数组边界, 类型转换缺乏检查系统


#### 并发编程的三个问题 和 volatile
- 原子性问题，可见性问题，有序性问题

1. 可见性:volatile保证一个线程修改了变量值,其他线程能够立即看到修改后的值。它通过在修改volatile变量时强制将值刷新到主内存,读取时强制从主内存重新读取来实现。  
2. 有序性: volatile 在同一时刻只能由一个线程进行获取 //有序. 即禁止volatile变量操作与其他内存操作重排序。
3. -原子性:volatile不能保证原子性。

#### 影响类的大小的因素
这些会影响：  
- 成员个数：每个成员变量都会占用内存空间，成员越多，类的大小就越大。  
- 是否有虚函数：如果类中含有虚函数，编译器会为该类生成虚函数表指针(vptr)，这个指针会占用额外的内存空间。  
- 对齐方式：内存对齐是编译器为了提高程序性能而采取的一种策略，不同的对齐方式会导致类的大小不同。比如4字节对齐和8字节对齐会产生不同的类大小。  
这些不影响：  
- 函数个数：普通成员函数不占用类的内存空间，因为它们存储在**代码段**中。  
- 虚函数个数：虚函数的数量并不直接影响类的大小，因为不管有多少个虚函数，类中只需要一个虚函数表指针。  
- 静态变量个数：静态变量属于类而不属于对象，它们存储在**全局数据区**，不会影响类的大小。

#### C 源代码编译流程

1. **预处理**：展开宏、处理 `#include` 等指令 → 生成 `.i` 文件
2. **编译**：将预处理后的代码转为汇编代码 → 生成 `.s` 文件
3. **汇编**：将汇编代码转为机器码（二进制目标文件） → 生成 `.o` 文件
4. **链接**：合并目标文件和库文件 → 生成可执行文件

```shell
gcc -E main.c -o main.i    # 预处理  
gcc -S main.i -o main.s    # 生成汇编  
gcc -c main.s -o main.o    # 生成目标文件  
gcc main.o -o program      # 链接  
```

| **参数**       | 作用                 | 示例                       |
| ------------ | ------------------ | ------------------------ |
| `-o <fname>` | 指定输出文件名            | `gcc -o program main.c`  |
| `-c`         | 只编译不链接（生成 `.o`）    | `gcc -c main.c`          |
| `-Wall`      | 启用所有警告提示           | `gcc -Wall main.c`       |
| `-O2`        | 优化级别（加速代码执行）       | `gcc -O2 main.c`         |
| `-g`         | 添加调试信息（GDB 使用）     | `gcc -g main.c`          |
| `-I<目录>`     | 添加头文件搜索路径          | `gcc -I./include main.c` |
| `-l<库名>`     | 链接动态库（如 `-lm` 数学库） | `gcc main.c -lm`         |
| `-L<目录>`     | 添加库文件搜索路径          | `gcc -L./lib main.c`     |

## STL

#### 下标操作
支持
1. vector(): 支持随机访问,可以通过下标直接访问元素  
2. deque(): 双端队列,支持随机访问,可以使用下标访问元素  
3. map(): 关联容器,可以通过键值使用下标访问元素  
4. unordered_map(): 哈希表实现的map,同样支持通过键值的下标访问  
5. string(): 字符串类型,支持通过下标访问单个字符  
  
不支持下标运算符`[]`的容器:  
  
6. list(): 双向链表结构,只能通过迭代器顺序访问,不支持随机访问  
7. set(): 集合容器,元素具有唯一性且有序,只能通过迭代器访问  
8. unordered_set(): 哈希表实现的集合,同样只能通过迭代器访问  
9. stack(): 栈结构,只能访问栈顶元素,不支持随机访问

## OOP 特性

#### 派生类继承
**可继承**
- 非静态成员函数 
- 私有成员: 是的, 会继承私有成员, 但没有访问权限
  
**不可继承**
- **构造函数**:  构造函数, **析构函数**以及**拷贝构造函数**都不能被继承,每个类都必须定义自己的构造函数。派生类可以通过构造函数初始化列表调用基类的构造函数,但这不是继承关系。  
- **静态成员函数**:  静态成员函数属于整个类而不是某个对象,它不能被继承。派生类可以访问基类的公有静态成员函数,但这是通过作用域解析运算符`(: :)`来实现的,而不是继承。  
- 赋值操作符:  赋值操作函数(**operator=**)不能被继承。每个类都需要定义自己的赋值操作函数,以确保正确处理该类特有的资源管理。

## 虚函数

#### 类中的 vptr
- 一个带虚函数且没有其他成员变量的类, 有一个实例 obj, 如果我们把`obj`看作是一个`void*`数组，那么`obj[0]`（即数组的第一个元素）可以被解释为vptr

#### 正确的获取 vptr 的方法
```cpp
#include <iostream>

class A {
public:
    virtual void foo() { std::cout << "A::foo\n"; }
    virtual void bar() { std::cout << "A::bar\n"; }
};

int main() {
    A* obj = new A();
    
    // 方法 1：将对象指针转为 void** 获取 vptr
    void** vptr_ptr = reinterpret_cast<void**>(obj);
    void* vptr = *vptr_ptr;  // 这才是真正的 vptr
    
    // 方法 2：直接访问对象内存的前 sizeof(void*) 字节
    void* vptr_direct = *reinterpret_cast<void**>(obj);
    
    std::cout << "vptr address: " << vptr << std::endl;
    delete obj;
    return 0;
}
```

#### 不能声明为虚函数的有
- 静态成员函数
- 内联函数
- 构造函数
