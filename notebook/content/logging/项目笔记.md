`filter_contours(index_, bg_iterator_->frame_contours_);` 过滤得到像球的轮廓
- 一共会有两次 match_contour 的调用
    - 第一次是以上次确定的参数
    - 如果没有成功匹配, 第二次以默认参数值再次匹配
- `match_contour` 
    - 获取轮廓的 moments(几何特征)
    - 根据面积, 轮廓密度, 外接矩型宽高比, 圆形度找出像网球的轮廓
    - 如果没匹配到则会放宽参数
- `filter_contours_by_area` 使用预测球心过滤轮廓
    - 回球
        - 方向不一致的直接跳过
        - 在前一帧或前两帧的预测框(is_in_rectangle)内则加入结果列表
    - 来球
        - 如果接近人体目标框 bbox, 则保留所有轮廓
        - 方向不一致或进入 bbox 跳过
        - 在前一帧或前两帧的预测框(is_in_rectangle)内则加入结果列表
    - else 保留所有 (表示是轨迹初始状态)
- 结果保存: `filtered_contours_`

`greed_get_roi`
- 加入每个 contour 自己的 roi
- 对每个 contour, 如果能与剩下所有 contour 在一个 roi, 加入此 roi
- 网球可能在的 roi 结果保存: `rois_`

`detect_roi` 在 roi 中检测网球目标框
- `detect_roi_by_model` 用指定模型检测单帧的所有 roi
    - 输入: nv12_data, 输出: {time_stamp: 单帧所有roi}
        - 将 nv12_data 转换为 cv:Mat 格式 
        - 使用 `GetNV12PyramidFromNV12Img` 将 cv:Mat 转为大模型需要的 `NV12PyramidInput` 格式. 
        - 重置和设置 dnn_node (使用的大模型) 参数
        - 执行 dnn 推理, 保存单帧**目标框**到 `dnn_node->ts_det_rois_`
    - 再次过滤目标框
        - 坐标映射：相对坐标 → 全局坐标
            - DNN 检测的是 ROI 内的目标，坐标是「ROI 内的相对值」，需要加上 ROI 在图像中的全局坐标（roi_x/roi_y），才能得到「图像全局坐标」
        - 筛选掉(与人框重叠&&(目标框置信度<50 || 与无效框重叠) 的框
            - [[#detect_roi_by_model 后半段流程]]
        - nms (非极大值抑制) 去除重复目标框, 只保留分数高的

`match_bbox()` 用轮廓匹配目标框
- 过滤与无效框(invalid_bbox) 重叠的框
- 通过「轮廓几何匹配（IOU / 面积 / 中心距离）」筛选与网球轮廓匹配的框；
    - `cv::minAreaRect` 取得轮廓的最小旋转矩形
- 对轮廓匹配失败的框，进一步通过「轨迹预测（直线距离 / 垂直距离）」补充匹配
- 结果保存到 `match_indices_`, 保存 index, 使用时为 `frame_bboxes_[id]`

`get_ball_pt()` 获取球心位置
- `calculate_pt_score` 计算每个可能的球心的分数
    - 方向与前两球方向不一致: 0
    - 与上一帧重合超过 0.2: 大模型误判, 标记为 999
    - 根据(点到前点距离)和(点到直线距离)计算一个分数
    - 多于三个点时, 用倒数第二个和第三个, 不要倒数第一个(防大模型?)
    - 当之前的轨迹只有一个球时:
        - 方向不对: 0
        - 仅根据到前点距离计算分数
- 如果空轨迹(第一个球), 直接使用第一个
- 找到分值最大的设为新球心

- `count_down_trajectory()` 匹配球心失败时的处理

    - 处理: 轨迹.is_over = true;
- 如果球心与无效目标框重叠, 清空球心和 pre球心, 重置轨迹
- 如果当前帧匹配到球心, 取轨迹最后一个点为 pre球心, 停止轨迹丢失倒计时
- 更新轨迹: push 球心

`get_ball_dpt()` 
- 没有球心/球端有2落地点/人端有1落地点 -> return
- speed_y > 0 -> 下落过程
- 如果此帧下落 // 没有连续上升3帧就下落，判断落点为误检, 放弃上个 dpt
- 如果此帧上升
    - `trajectory_have_descend` 直接比较两个连续点 或许能只更新最新的点
    - 没到三帧连续上升就有下降了(212), 取 size-2 为 dpt
- 落点判定逻辑
    - `atan2(y, x)`：计算向量与 X 轴的夹角(弧度), 角度越大 → 运动越垂直
    - -2-3 比 -3-4 垂直 -> -2-3 还在落 -> -2  是落点
    - 角度突变(20°) -> -2-3 是反弹轨迹 -> -3 是落点
    - 否则交给 ball_tracker_ 检测
        - 把疑似落地点 -2 排除 用剩下的轨迹点重新拟合抛物线 预测这个疑似点应该在什么 Y 坐标 -> 不是 -2 就是 -3

`ball_polynormal_fit()` 球端拟合
- 预处理: 轨迹未更新或者点太少直接返回
- 根据第一落点切成两段拟合
- 第二段拟合失败则删除最后一个点重新拟合
- 都拟合失败则返回
- 保存轨迹片段和拟合后的落点(与人端逻辑相似)

`human_polynormal_fit()` 人端拟合
- 三段: 0, 1, 2
- 预处理: 轨迹未更新或者点太少直接返回, 清空旧数据
- 拟合
    - 来球切为两段分别拟合, 回球再一段拟合
    - 特殊情况：检测出轨迹1, 3, 轨迹2完全没有点, 将轨迹2当作一次函数进行拟合
- 保存
    - 0 || 1 拟合成功
        - 0 保存到 ball_fit_pts
        - 0 && 1: 用 ball_fit_pts 更新拟合的第一落点
        - 保存 1
    - 都不成功: 重置轨迹片段和系数
- 处理击球点
    - 没有检测到 1: 2 第一点为击球点
    - 否则击球点为 1, 2 延长交点

`update_bboxes()` 更新历史目标框, 无效目标框
- **无效框** = 重复出现、位置不动、干扰物
- **历史框** = 保存最近 10 帧所有非球、非人体框
- `frame_bbox`: 新检测的可能是目标框的 **其中一个框**
- 无效框
    - 跟踪无效框变化: 如果 frame_bbox 与无效框重叠, 将重叠的那个无效框更新为 frame_bbox 的坐标
    - 筛选新无效框: frame_bbox 与历史框重叠 -> 静止/误检
    - 无效框只保留 10 个
- 历史框
    - 除了真球心 和 人体目标框中的网球目标框, 其他全部加入
    - 保留最近 10 帧的历史框

`check_trajectory_error()`
- 按 2/1/0 的顺序选择 check 对象 (我们要 check 的是最新的轨迹)
- 0 段可能受到落地球干扰, 检测 2 帧, 其余 1 帧

### ball_synth

`inverse_projection()` 输入 2d 点和相机参数, 得到相机中心及其指向 2d 点的单位向量
- 相机内参矩阵 `K` 会把 3D 方向 “压缩扭曲” 成像素坐标 (x,y) 
- 旋转矩阵有一个数学特性： 逆矩阵 = 转置矩阵, 而 transpose 矩阵总是计算更稳定

```cpp
// 相机参数矩阵 K, 旋转矩阵 R, 平移矩阵 t
// 还原旋转和平移
Eigen::Vector3d camera_center = -1 * R.transpose() * t; 
//给 2D 点(x,y)补一个1，变成齐次坐标
Eigen::Vector3d pt(pt_2d[0], pt_2d[1], 1); 
//把像素点还原成相机坐标系里的方向向量
Eigen::Vector3d pt_normalized = K.inverse() * pt; 
// 相机坐标系 -> 世界坐标系
Eigen::Vector3d ray_vector = R.transpose() * pt_normalized;
ray_vector.normalize();
```

`fix_pt_PnP()` 利用网球是圆形 + 已知直径，通过 PnP 精确计算网球到相机的距离，再结合射线反投影，修正网球的 3D 坐标
- 调用 cv::solvePnP
    - 输入： - 3D 点（真实物理位置） - 2D 点（图像像素） - 相机内参
    - 输出： - 相机 → 球心的 **旋转 R** - 相机 → 球心的 **平移 T**
- 根据 T, 算出相机到网球的距离
- 然后调用 `inverse_projection()` 算出投影方向, 方向 \* 距离得到修正后的 3d 点
- 普通三角化 / 射线交会： - 只能知道**方向** - 不知道**距离**

### pose_detection

进程启动后创建 `PoseDetectNode`，在独立线程里从图像队列取 NV12，调用 `PoseDetection::image_process` 做检测/姿态/分割/球拍后处理，再按 topic 发布人体框、裁剪图和关键点列表。

1 运行与生命周期层
- 负责节点启动、配置、激活、停机。
- 代表代码：`main_pose_detect.cpp`、`PoseDetectNode::handle_configured/activate/deactivate`。
- 作用：决定什么时候订阅/起线程/进入可处理状态。

2 接入与并发调度层
- 负责图像接入、队列、线程协作、参数门控。
- 代表代码：`Sharedimage_callback`、`mipiImgProcess`、`frame_cv`/`frame_mtx`、`is_getparam_`。
- 作用：把外部实时流稳定转为内部可消费任务流。

3 感知推理层（模型执行层）
- 负责 det / kps / seg 三类模型推理执行与回调同步。
- 代表代码：`detect_person`、`detect_kps`、`segment_roi`、`PostProcess`。
- 作用：从图像得到原始感知结果（框、关键点、mask/轮廓）。

4 状态机与跟踪决策层
- 负责 `LOST/INIT/TRACKING/LOSTING` 迁移、目标选择、速度估计。
- 代表代码：`update_person_action`、`select_bbox`、`shift_roi`。
- 作用：把“瞬时检测”变为“连续目标轨迹”。

5 时序融合与几何后处理层
- 负责坐标反变换、ROI 平滑、球拍轮廓与关键点融合。
- 代表代码：`update_person_info`、`update_historic_rois`、`process_rois`、`get_published_rois`、`RacketDetector`。
- 作用：把批处理稀疏结果变成连续、稳定、可发布的数据。

6 发布与下游接口层（发布层）
- 负责把最终结果封装为 ROS 消息并对外输出。
- 代表代码：`publish_bbox`、`publish_roi_img`、`publish_pose_array`。
- 作用：向 ball_detection / image_codec / pose_synth 提供统一接口与语义（有效/无效、帧号、时间戳、相机名）。

`miniProcess()`
- 在 `frame_mtx` 下 pop 队头 → 再持 `g_mutex_` 等 `is_getparam_`（最长约 3s） → 若仍无参则 return，该帧已出队、不会放回 → 否则 `image_process` + `publish_msg`。

- 在跟 && 无效 -> 不发布
- 不在跟 -> 发布 "丢失消息"

`publish_roi_img()`

`publish_pose_array()`

`PoseDetection::init()`
- 这是算法的初始化(不是节点), 模型与配置装载
- 人体检测模型 dnn_det, 走自定义的 dnnInit()
- 分割模型 dnn_seg
- 姿态模型 kps, 走 DnnNode 基类 Init()

`PoseDetection::process_pose()`
- `State::LOST`/`State::LOSTING`  -> 检测人体目标
    - 裁剪 roi, 检测人体位置, 更新人体状态
- 非丢失状态: 核心是缓存帧 + 抽帧姿态 + 批量后处理
    - 一次有 detect_num_ 帧, 才一起批量处理. 本批次在 `detect_imgs_` 中
    - 检测人体关键点, 分割球拍并获取球拍关键点
    - 更新信息
    - 生成裁剪 rois
- 收尾: 打日志, 重置 api 时间, 抽帧渲染和保存

`get_published_rois()`
- 从 `historic_rois_`（历史 ROI 轨迹）中做平滑与插值，生成 `publish_rois_`（待发布 ROI 队列）。
- `pre_nv12_data_` 是从 save_data() 存进来的, 这是未抽帧的原始图像
- 轨迹短时, 暂不发布或用小窗口做平滑
- 轨迹足够长时, 在历史窗口中取样

`process_roi_img()`
- 把 `pre_nv12_data_` 和 `publish_rois_` 对齐，真正裁出 `roi_img_`，供节点层 `publish_roi_img()` 发布
- 输入原始图像, 输出 roi, 每一原始帧都对应一个待发布的 ROI

`detect_kps()`
- 本批次的推理, 逐帧推理(异步)
- `DnnNode::Run` 背后的引擎/线程池在任务结束时调用 `PostProcess`；具体是哪个 pthread 由 `t_dnn_node`/底层实现决定
    - `PostProcess()` 负责解析并转换数据格式
- output: 对已经裁好的 `detect_imgs_` 里每一张 ROI 子图做推理, 得到 `detect_bboxes`, `detect_kpts`, 帧号 -> 本帧结果 vector
- 所有线程的推理任务结束后(由 `_is_process_` 确认), 开始收尾
    - roi 还原到原图分辨率
    - 按 roi 中心选 nerest bbox / kpts
    - 更新

`segment_roi()`
- 推理流程与 `detect_kps()` 类似, 但后处理放在本函数中
- 输入输出`detect_kpts_`：在现有人体关键点 map 上追加/改写球拍关键点
- 后处理部分
    - 还原 roi 分辨率, 转二值图找到球拍外轮廓(如有多个, 选择离 last_roi 最近的), 还原全图坐标
    - 如果没有任何一帧输出有效轮廓, 则本批全部无效
- 存进 `racket_contours_`
```cpp
    // 分割模型回调已把每帧结果写入 dnn_seg_->ts_seg_masks_；此处仅在有数据时做后处理
    if (!dnn_seg_->ts_seg_masks_.empty())
    {
        cv::Mat seg_img;   // 临时二值图：在 proto 分辨率上铺 mask 点
        uchar* ptr;
        // 整批里是否至少有一帧得到有效轮廓；若全批无效则最后清空 racket_contours_
        bool is_valid = false;

        // 假设分割 head 输出为输入尺寸的 1/4（常见为 stride=4 的 proto）
        int proto_width = seg_model_input_width_ / 4;
        int proto_height = seg_model_input_height_ / 4;

        // person_infos 末尾连续 detect_num_ 条对应当前 seg_imgs_
        int pi_idx = person_action_.person_infos.size() - detect_num_;

        // 按 ts_seg_masks_ 的顺序逐帧处理（顺序应与 img_infos_/本批 person_infos 一致）
        for (auto & ts_seg_mask : dnn_seg_->ts_seg_masks_)
        {
            // 该帧人体裁剪 ROI：用于把「ROI 子图/模型坐标」映射回整幅原图
            Roi roi = person_action_.person_infos[pi_idx].roi;

            // 类别 id -> 该类在 proto 栅格上的轮廓点集
            std::map<int, std::vector<cv::Point>> seg_contours = ts_seg_mask.second;
            std::vector<std::vector<cv::Point>> contours; // findContours 后、已放大到模型输入尺寸的轮廓
            std::vector<cv::Point> target_contours;        // 本帧最终选中的单条球拍轮廓（全图坐标）

            // 只使用类别 0 的轮廓点（约定为要提取的目标，如球拍）
            if (!seg_contours.empty() && !seg_contours[0].empty())
            {
                // 将 proto 上的点铺成二值图，便于得到闭合外轮廓
                seg_img = cv::Mat::zeros(proto_height, proto_width, CV_8UC1);
                ptr = seg_img.ptr<uchar>(0);
                for (const auto& pt : seg_contours[0])
                {
                    int idx = pt.y * proto_width + pt.x;
                    ptr[idx] = 255;
                }

                // 在 proto 分辨率上提取外轮廓
                std::vector<std::vector<cv::Point>> proto_contours;
                std::vector<cv::Vec4i> hierarchy;
                cv::findContours(seg_img, proto_contours, hierarchy, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);

                // 将每条轮廓从 proto 放大到 seg 模型输入尺寸，再按 ROI 映射到全图坐标
                for (const auto& proto_contour : proto_contours)
                {
                    std::vector<cv::Point> contour;
                    for (const auto& proto_pt : proto_contour)
                    {
                        cv::Point pt;
                        // proto -> 模型输入宽高
                        pt.x = proto_pt.x * seg_model_input_width_ / proto_width;
                        pt.x *= roi.ratio;
                        pt.x += roi.x;
                        pt.y = proto_pt.y * seg_model_input_height_ / proto_height;
                        pt.y *= roi.ratio;
                        pt.y += roi.y;
                        contour.push_back(pt);
                    }
                    contours.push_back(contour);
                }

                // 多轮廓时选离人体 last_roi 中心最近的一条作为本帧球拍轮廓
                this->select_contour(target_contours, contours, roi.size);
            }

            // 只要有一批里出现过有效轮廓，is_valid 置 true，避免最后被整批 clear
            if (!is_valid && !target_contours.empty())
            {
                is_valid = true;
            }

            // 每帧压入一条轮廓（可为空），顺序与批内帧序一致，供 RacketDetector 使用
            racket_contours_.push_back(target_contours);
            pi_idx++;
            RCLCPP_DEBUG(rclcpp::get_logger("pose_detection"), "racket contour pt num:%zu", target_contours.size());
        }

        // 若本批所有帧都没有有效轮廓，丢弃已 push 的内容，后续走「无球拍轮廓」逻辑
        if (!is_valid)
        {
            racket_contours_.clear();
        }
    }
```

`update_person_info`、`update_historic_rois`、`update_bbox`（发布前状态闭环）
- `update_person_info`：把本批 `detect_kpts_ / detect_bboxes_` 按时间戳写回 `person_action_.person_infos`（每帧一条结构化记录）。
- `update_historic_rois`：把本批 ROI（优先用 bbox 中心修正）加入 `historic_rois_`，并限制长度（最多 20）。
- `update_bbox`：基于 `person_action_.last_roi` 和最近观测，生成最终的 `person_bbox_`（给 `publish_bbox` 用）。

`update_person_action()`
- 最新批有效: 
    - if LOST -> INIT
    - if TRACKING -> 更新跟踪速度
    - 用当前 bbox/关键点中心修正 last_roi, 限制 roi 必须包括人体, 并更新 last_roi
- 最新批无效:
    - TRACKING -> LOSTING
    - LOSTING 超过5帧 -> LOST, 重置 person_action_
- `last_roi` 同时被用于“下一帧裁剪先验”和“最近目标选择中心”, 短时会漂移，但系统设计了回拉通道。

`preprocess_pose()` + `shift_roi()`
- 把姿态推理要看的区域准备好
- 如果 last_roi 不可靠, 或根据速度微调 roi 后超出图像边界, 本帧放弃姿态推理
- 先将 `shift_roi` 存入 person_action_(本帧的 kpt 和 bbox 会在 detect_kpt()/segment_roi() 填入), 然后再裁剪和调尺寸

`preprocess_det`：生成人体目标框预处理图像. 把当前帧变成检测模型输入（整图或基于先验 ROI）

`detect_person`：调用 `dnn_det_` 推理, 检测单帧所有人体目标框, 并映射回原图坐标
- `select_bbox`：从多个候选里选“最合适”的框（LOST 看图像中心，非 LOST 看离 `last_roi.center` 最近）
