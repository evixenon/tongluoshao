# Global Codex Guidance

本文件是跨项目生效的 Codex 全局约定。项目根目录或子目录中的 `AGENTS.md` 可以补充或收紧这些规则；项目规则优先于本文件中的通用偏好。

## 任务授权

根据用户请求区分操作范围：

- 对于解释、评估、审查、诊断和计划请求：检查相关材料并报告结果，不主动修改代码或文档。
- 对于修改、构建和修复请求：自主完成范围内的本地修改，并运行相关的非破坏性验证。
- 对于外部系统写入、破坏性操作、购买、影响其他人员或显著扩大范围的行为：先获得用户确认。

能够通过文件、代码、测试、配置或工具确认的事实，不要询问用户。

## 工作方式

- 先阅读相关项目规则、README、测试和配置，再决定如何修改。
- 遵循项目已有的命名、目录、工具和验证约定；不要仅因本文件而创建项目结构。
- 修改前确认当前行为、目标行为、成功标准和受影响的边界。
- 设计或重构时，优先用清晰的小接口隐藏复杂性，并避免只为抽象而增加层级。
- 修复问题时优先建立可重复的失败信号，区分观察事实与待验证假设，并修复根因。

## 测试与验证

- 开发过程中优先运行与改动直接相关的增量测试。
- 当改动跨越公共边界、影响共享基础设施、存在较高回归风险、项目规范要求，或准备合并/发布时，运行更广范围的验证。
- 只在用户明确要求时运行全量测试
- 测试应优先验证公共接口的外部可观察行为，而不是实现细节。
- 最终回复中说明执行过的验证，以及未执行的关键验证及原因。

## 文档与长期知识

- 如果项目存在项目级 `AGENTS.md`、`CONTEXT.md`、ADR、模块文档或事实文档，按其规则渐进式读取和维护。
- 只有在本次任务改变了长期有效的架构决定、模块职责、领域规则、系统不变量或重要约束时，才更新 repo intelligence。
- 不要把聊天摘要、调试日志、当前 issue 状态或未经验证的推测写入长期知识。
- 发现文档与实现冲突时，不要静默忽略；根据任务意图和证据修正正确的一方，无法确定时向用户报告。
- 不要仅因全局规则而创建 `CONTEXT.md`、`docs/` 或其他知识目录。

## 文件与安全

- 只修改用户请求范围内或实现该请求所必需的文件。
- 只清理本次任务创建、确认不再需要且不被其他工作使用的临时文件。
- 不删除、覆盖或移动所有权不明的文件。
- 保留用户已有的未提交修改；修改前先区分它们与当前任务的变化。

## 输出

- 先给结论，再给必要的证据、风险和下一步。
- 使用中文为主；代码标识符、命令、路径和业界通用术语保持原样，必要时附英文注释。
